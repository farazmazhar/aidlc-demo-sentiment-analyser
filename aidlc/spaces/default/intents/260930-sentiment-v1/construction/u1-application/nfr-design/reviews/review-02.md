### Summary

The design's core NFR choices are real and contract-aligned - single loopback bind constant, redaction by construction, one error builder, injected transport carrying the timeout, no pooling/caching layer, and logical components that map cleanly onto the domain catalogue (Configuration, Persistence, SentimentEngines, AnalysisService, WebSurface) with ADR-003's in-process handoff accounted for. Two Major issues remain: the concurrency claim for store access contradicts the functional design's allowed overlapping submissions, and the reliability design's offline-fallback claim contradicts the BR1.4 / contract-503 live-without-key refusal, which no component owns. The remaining items are documentation/coverage gaps (traceability omissions, unbounded history limit, missing blast-radius view, uncited upstream artifacts) that do not block implementation but are worth fixing before the verification chain depends on them.

Needs a Request Changes at the gate only if the human wants R-01/R-02 resolved now.
