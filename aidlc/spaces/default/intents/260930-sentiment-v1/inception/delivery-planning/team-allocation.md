# Team Allocation — `very-cool-sentiment-analysis` v1

A Bolt is one build pass over a piece of the work, ending in something that runs; a mob is the group
that owns a Bolt and approves its result.

## Allocation

| Bolt | Mob | Notes |
|---|---|---|
| 1 — Converge the v1 contract, storage and engine paths, then finish the interface | `aidlc-developer-agent` (AI, one session) | One unit, one Bolt, one owner |

## Why one owner

Team Formation (the Ideation stage that would allocate named teams) did not run in this scope: the
`classic` scope skips the whole Ideation phase, so no team roster exists to allocate against. The
default for a skipped Team Formation is that every Bolt is executed by `aidlc-developer-agent`, which
is what this plan records.

Nothing in the intent needs more than one owner: there is one unit, one Bolt and one person's work.

## Program Board

Not applicable. A Program Board exists to show several teams' Bolts against each other's
dependencies; with one Bolt and one owner there is nothing to plot.

## Approval rhythm

The intent runs with Construction Checkpoints enabled and unit-major iteration, so each unit's
applicable design stages and Code Generation run serially, followed by its verified completion
checkpoint. The verification command and the staffing choice are confirmed separately with the human
at the end of this stage; this file records only who owns the Bolt.
